## Summary <a id="summary"></a>

An XProc pipeline that runs one or more gradle test tasks and generates an HTML report summarising the aggregated results, for example: all official XPath and XQuery tests for SaxonJ-HE.


## Usage Guide <a id="usage"></a>

The workflow is generally:

1. Pull the latest code from whichever branch of `Saxondev` you intend to check, eg. `saxon12` or `main`
1. Run `./gradlew clean`
1. Run `src/aggregate_test_results.xpl` (_see [Running from the command-line](#how-to-run), below_), which by default will:
	1. Run the `aggregated-test-results` gradle task for each SaxonJ product
	1. Create an XML file containing all the results from the tests run, storing it in the `$output-dir` as `aggregated_test_results.all.xml`
    1. For each test suite version:
        1. Create an XML file, containing the subset of test results from that test suite, storing it in the `$output-dir` as `aggregated_test_results.{test suite version}.xml`
        1. Generate an HTML report summarising the test results, grouping them by:
              * Result category (pass, fail, wrongError, notRun, etc.)
              * Reason
              * Test set
        1. Store the report in `$output-dir` as `aggregated_test_results.{test suite version}.html`        
    1. Output a directory listing of `$output-dir`
1. Review the HTML reports		


### Runing from the command-line <a id="how-to-run"></a>

#### Using XML Calabash
```powershell
java -jar /path/to/calabash.jar src/aggregate_test_results.xpl
```

To download the latest version of XML Calabash, see [https://codeberg.org/xmlcalabash/xmlcalabash3/releases](https://codeberg.org/xmlcalabash/xmlcalabash3/releases)

For documentation on setting it up, see [https://docs.xmlcalabash.com/userguide/current/part-install.html](https://docs.xmlcalabash.com/userguide/current/part-install.html)

### Default settings <a id="defaults"></a>

By default, this pipeline will:

* run the following gradle tasks:
    * `java:he:aggregated-test-results`  
* store the results in `tools/aggreagate-test-results/out/YYYYMMDD/`

## Inputs <a id="inputs"></a>

### Product list

_Via the `source` port._

An XML file listing the products to test and for each product:
* the name of the gradle task to run
* a path to where the gradle task is expected to save the test results

### Run tests

_Via the `run-tests` option._

Set to `true` if you wish to run the gradle tasks or `false` if you instead simply wish to generate reports from existing test results.

If set to `false`, you will also need to set the `date` option unless the tests were run today.

_See [Default settings](#defaults), above_


### Date

_Via the `date` option._

Only relevant if `run-tests` is set to `false`.


### Output directory

_Via the `output-dir` option._

A path to the directory in which this pipeline will store all its outputs.

_See [Default settings](#defaults), above_


## Outputs <a id="outputs"></a>

### Aggregated test results XML

* `aggregated_test_results.all.xml` collects together the XML files generated by all the gradle test tasks run by this pipeline. 
* `aggregated_test_results.31.xml` is the subset of `aggregated_test_results.all.xml` generated by the QT3 test suite.
* `aggregated_test_results.40.xml` is the subset of `aggregated_test_results.all.xml` generated by the QT4 test suite.

### HTML reports

* `aggregated_test_results.31.html` summarises the results in `aggregated_test_results.31.xml`
* `aggregated_test_results.40.html` summarises the results in `aggregated_test_results.40.xml`
