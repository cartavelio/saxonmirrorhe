Generate Product Variant Datasheets

This stylesheet generates HTML and FO versions of the product variant datasheets.

Directions for use

Define the product variant components in the main XML file (currently a file named 'prod-desc-version.xml').

Edit the main styling required in the CSS stylesheet (default saxondocs_new.css). This will be mostly sizing, colours, fonting, space before/after, indenting etc.

Change the page size and header/footer sizes in the file config.xml. (In future we could also add additional sections that could be added for example to the header.]

Run this stylesheet (prod-desc-to-fo.xsl) in Saxon (either independently or under Oxygen) under XSLT 3.0 mode, with the product details file as input.

The results will appear as a set of HTML and FO files. The HTML files are all in a directory html/, the FO in an fo/ directory.

Use FOP (e.g. under Oxygen) to convert FO to PDF files. [Note - make sure the PDF file isn't open in Acrobat - it's a common problem.]

If you run under Oxygen, then you may be able do a batch conversion of the FO files to PDF by selecting each of them, right click, and 'Transform/Apply Transformation Scenario' - the default for FO files is to generate the PDF. I may also be able to include the last two as a single step if this is required.

Technical details

This stylesheet is designed as follows:

  • The variants required are a sequence of string names as the parameter $variants, e.g. 'HE','PE' etc. The default value is the current set of product variants.

  • The input is a product details XML structure, where each section that is variant-specific is decorated with a @variant attribute containing a whitespace-separated list of the variants it relevant to, e.g. variant="PE EE".

    Top level sections of this structure can be decorated @class="header|footer", which will collect them into a header and a footer section respectively.

  • A set of datasheets is collected for each variant, using mode variant. These are stored in a map, as are all results.

  • Each definition is converted into an HTML document using mode doc. The overall template for these documents is defined in an XSLT template (stored separately in prod-desc-template.xsl) . These HTML documents are styled though a CSS stylesheet, whose name is a parameter $CSS, which, if relative, is resolved relative to the input data.

  • The bodies of these documents are converted into XSL-FO sources, first by styling (using a function jwl:applyCSS($stylesheet.URI,$doc) that applies CSS properties to an XML tree leaving the results as attributes), then by using the mode FO to produce XSL-FO instructions, which is defined in the stylesheet prod-fo.xsl

  • The results appear in 'variant-prod-desc.xml' files for the HTML and 'variant-prod-desc.fo' files for the FO source

  • Use FOP to convert the FO files.

Required resources

  • prod-desc-to-fo.xsl - the main stylesheet to be evaluated over the product description.

  • prod-desc-template.xsl - the overall HTML template used to define the outer shell of the HTMLresults.

  • prod-fo.xsl - converts (styled) HTML to FO

  • css2xslt.xsl - applies CSS to an XML tree, leaving results as attributes. This resource is now held in {repository}/src/he/data/lib, and linked to by a relative path from the stylesheet prod-desc-to-fo.xsl. If you move this directory, you'll need to change teh path

  • self-doc.xsl - self-documents a document.

  • config.xml - configuration file for things like page size and headers and footers.

Restrictions & shortcomings

  • Relative column widths can be used by styling width:75% through CSS onto table cells. Currently this will work for styling just one column, but is erroneous beyond that.
